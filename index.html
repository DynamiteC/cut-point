Find the second when people stop watching.

CutPoint reads how long each person watches a video. It finds the exact second when many people leave. It then looks at those frames and tells you what is on the screen. It writes short notes that a video editor can use. It does this without a person asking it to.

How CutPoint works

The five steps always run in the same order. The code sets that order. A model never chooses what happens next. Every measurement comes from the database: the seconds, the percentages and the counts. A model only rates how bad a moment is, and how sure it is.

STEP 00
Watcher
The watcher starts the work. Every 15 minutes it looks for new drops. If nothing changed, it stops and spends nothing. If a new drop is there, it starts all five steps. No person is part of this.
Cloud Scheduler • Pub/Sub
STEP 01
Analyst
The analyst asks the database where people left. It reads the numbers directly. The connection is read-only, so it cannot change the data. No model is part of this step.
ClickHouse • read-only
STEP 02
Extractor
The extractor cuts the video. For each drop, it takes the 5 seconds before and the 5 seconds after. It uses ffmpeg in a private service on Cloud Run.
ffmpeg • Cloud Run
STEP 03
Diagnostician
Gemini looks at each clip. It says what is on the screen. It then gives the most likely reason that people left at that moment.
Gemini 3.5 Flash
STEP 04
Narrator
Gemini writes a short summary for the editor. It can use only the facts above. The system removes the summary if it names a second that is not a real drop.
Gemini 3.5 Flash
STEP 05
Reporter
The reporter puts everything together. It writes the notes in three forms: JSON, Markdown and a web page. It saves them to Firestore and Cloud Storage.
Firestore • Cloud Storage

What it does, and how fast

Each number below comes from a test or a benchmark in this repository. The commands that produce them are in the README. Nothing here is an estimate.

SCALE
9.92 million events
The database holds one row for each second that each person watches. CutPoint reads all of it to find the drops. A materialized view keeps the count of viewers per second ready in advance.
make verify-data
SPEED
102 ms
This is the slowest 1 percent of API calls, with 50 people asking at the same time. The middle 50 percent are much faster. The database work is the small part; the video work is the slow part.
make load-test
INGEST
267,891 rows/sec
This is how fast the loader writes new watch data into the database. The loader saves its place as it goes, so a stopped load starts again from the same point.
make load-test
TRUST
0 measurements from a model
A model writes the words, and rates how bad each moment is. A model never measures anything. Every second, percentage and count comes from the database. Each report shows this figure, so you can check it yourself.
app.html
CONTROL
0 false drops
One test video has no drop in it at all. CutPoint finds nothing in that video and says so. This shows that it does not simply find what you tell it to find.
demo_control
TESTS
83 tests
The tests cover the database queries, each of the five steps, the login rules and the reports. Four more tests break parts of the system on purpose to check that it fails in a safe way.
make verify-all

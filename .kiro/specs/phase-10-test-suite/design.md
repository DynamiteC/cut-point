# Design: Phase 10 Test Suite

## Architecture Overview

Phase 10 adds five test categories as additive test infrastructure. Each category produces a gate (Makefile target) and a documentation artifact for the demo video.

```
scripts/smoke.sh            -> make smoke (Phase 10.1)
tests/load/ingest_load.py   -> make load-test (Phase 10.2)
tests/load/api_load.py      -> make load-test (Phase 10.2)
scripts/load_report.py      -> docs/perf/load-report.md + load-chart.png
tests/stress/find_breaking_point.py -> make stress-test (Phase 10.3)
tests/chaos/test_*.py       -> make chaos-test (Phase 10.4)
tests/soak/short_soak.py    -> make soak-test-short (Phase 10.5)
```

## Component Design

### 10.1 Smoke Test (scripts/smoke.sh)

A bash script that:
1. Starts local ClickHouse from `.local-clickhouse/clickhouse server` in background
2. Waits for ClickHouse readiness (poll SELECT 1 via curl to HTTP interface)
3. Runs each check sequentially with set -e (fail-fast)
4. Traps EXIT to kill the ClickHouse process on any exit path
5. Each check prints a pass/fail line for visibility

Dependencies: local ClickHouse binary, uv, ffmpeg

### 10.2 Load Test

**ingest_load.py**: Uses clickhouse-connect directly to:
- Generate synthetic batches of 10k/50k/100k rows
- Insert via client.insert() with timing
- Compute p50/p95/p99 from repeated iterations
- Query retention_curve.sql and changepoints.sql using concurrent.futures.ThreadPoolExecutor (20 iterations x 3 trailers)
- Output: JSON results file at tests/load/results/ingest_results.json

**api_load.py**: Uses httpx.AsyncClient with asyncio.Semaphore for concurrency control:
- Hit GET /trailers and GET /report/{id} at 10/50/100 concurrent requests
- Compute latency percentiles and error rate
- POST /analyze capped at 3 concurrent (explicit Gemini quota comment)
- Output: JSON results file at tests/load/results/api_results.json

**load_report.py**: Reads both JSON results, generates:
- docs/perf/load-report.md with tables
- docs/perf/load-chart.png via matplotlib (latency-vs-concurrency)

### 10.3 Stress Test

**find_breaking_point.py**: 
- Linear ramp on GET /report/{id}: starts at 10 concurrent, adds 10 per iteration up to 500
- Stops when error_rate > 5% or p99 > 10s
- Separate stress loop for segment extractor /extract: starts at 2 concurrent, adds 2 per iteration
- Stops when latency exceeds 3x the baseline (first iteration)
- Output: docs/perf/stress-report.md

### 10.4 Chaos Test

Four pytest test files in tests/chaos/:
- `test_chaos_extractor_kill.py`: Uses subprocess to start extractor, starts pipeline, kills extractor mid-run, asserts error message and no partial report
- `test_chaos_clickhouse_port.py`: Patches CLICKHOUSE_HOST env to wrong port, asserts actionable error within timeout
- `test_chaos_corrupt_video.py`: Creates a corrupt video file, runs extraction, asserts per-clip error handling and continuation
- `test_chaos_gemini_timeout.py`: Mocks the Gemini client to raise TimeoutError, asserts retry behavior and blast-radius containment

Each test has a docstring explaining the failure mode it validates. A conftest.py generates chaos-report.md from test results.

### 10.5 Soak Test

**short_soak.py**: 
- CLI with --minutes flag (default 30)
- Runs the pipeline in --dry-run mode in a loop (avoids Gemini calls)
- Logs RSS memory via psutil (or resource module) every 60s
- Asserts final_rss <= initial_rss * 1.2
- Output: docs/perf/soak-report.md with memory trace

### Makefile Targets

Added to the existing Makefile (appended, not modifying existing targets):
```makefile
smoke:
	bash scripts/smoke.sh

load-test:
	$(UV) python tests/load/ingest_load.py
	$(UV) python tests/load/api_load.py
	$(UV) python scripts/load_report.py

stress-test:
	$(UV) python tests/stress/find_breaking_point.py

chaos-test:
	$(UV) pytest tests/chaos/ -v

soak-test-short:
	$(UV) python tests/soak/short_soak.py --minutes 30
```

### Dependencies Added

In pyproject.toml [dependency-groups] dev:
- matplotlib>=3.9.0 (for load-chart.png generation)
- psutil>=6.0.0 (for RSS memory monitoring in soak test)

## Data Flow

```
Load test:
  ingest_load.py -> ClickHouse (direct insert) -> ingest_results.json
  api_load.py -> FastAPI -> ClickHouse (read) -> api_results.json
  load_report.py reads both JSON -> load-report.md + load-chart.png

Stress test:
  find_breaking_point.py -> FastAPI/extractor -> stress-report.md

Chaos test:
  pytest tests/chaos/ -> chaos-report.md (generated by conftest fixture)

Soak test:
  short_soak.py -> pipeline --dry-run loop -> soak-report.md
```

## Constraints

- All work is additive: no Phase 0-9 files modified
- matplotlib and psutil are dev dependencies only
- smoke.sh manages its own ClickHouse lifecycle (start/stop)
- Load/stress tests assume ClickHouse is already running (started by smoke or manually)
- Chaos tests mock/patch rather than requiring live infrastructure where possible
- Soak test uses --dry-run to avoid Gemini quota
